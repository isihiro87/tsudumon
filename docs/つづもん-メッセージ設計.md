- 想定読者は中学生本人と保護者の両方。料金・解約の話は敬体、学習の話はやわらかいタメ口。

## 3. 決定事項（2026-07-26・ユーザー決定）

| 論点 | 決定 |
|---|---|
| 継続中の定期接点（C-3） | **毎日1単元を配信する**（LPの約束どおり）。JST 19:00 |
| 未体験フォロー（A-5） | **友だち追加から2日後＋7日後の2通**。体験・登録した人には送らない |
| 事務連絡（C-4／C-5／C-6） | **3つすべて入れる**（決済失敗・解約受付・期限終了の翌日） |

### 決定に伴う付随対応

- `aiChatPrompt.ts` の `TSUDUMON_SERVICE_KNOWLEDGE` は「毎日配信はつづもんに無い」と
  AIに教えているので、**日次配信の実装と同時に必ず書き換える**（放置するとAIが商品を否定する）。
- 日次配信の1通は「その日の1単元」。**サーバ側にWeb教材の進捗が無い**（`tzmwb-*` /
  `tzmref-*` は端末の localStorage）ため、第1段階は `tsudumonDaily/{uid}.cursor` で
  **カリキュラム順に1単元ずつ**進める。LINE経由の演習は `answers`（`source:'workbook'`）に
  残るので、ニガテ優先の出し分けは記録が溜まってからの第2段階とする。
- 送信は1日1通まで。日次配信と体験リマインドが同じ日に当たることは無い
  （体験中はライセンス種別が `trial` なので日次配信の対象から外す）。

## 3-1. 配信時刻（ユーザー設定・2026-07-26 実装／デプロイ済み）

「今日の1単元」が届く時刻は、**平日と土日で別々にユーザーが選べる**（例: 平日は夕方17時、土日は朝8時）。

| 項目 | 値 |
|---|---|
| 選択肢 | 6・7・8・9・10・15・16・17・18・19・20・21 時（JST） |
| 既定値 | 平日 19時／土日 10時 |
| 保存先 | `tsudumonDaily/{uid}.weekdayHour` / `.weekendHour` |
| 設定UI | `https://tsudumon.jp/account/`（「『今日の1単元』が届く時刻」） |
| API | `tsudumonSchedule`（POST `{idToken}` で取得、`{idToken, weekdayHour, weekendHour}` で保存） |
| cron | `tsudumonDailyUnit` は **毎正時**に起動し、その時刻を選んでいる人だけに送る |

- 不正値・選択肢外はサーバ側で既定値に丸める（`normalizeHour`）。
- 土日判定・時刻判定はすべて **JST基準**（`isWeekendJst` / `jstHour`）。
- 同じJST暦日に2回送らないよう `lastSentDate` で冪等。
- 走査は `active == true` × 該当時刻フィールドの複合インデックス2本
  （`firestore.indexes.json` に定義・デプロイ済み）。

**使う Firestore コレクション**

| コレクション | 作成者 | 用途 |
|---|---|---|
| `tsudumonFollowUps/{uid}` | 友だち追加（A-5）／解約・失効（C-6） | `followedAt` / `sentIntro.{day2,day7}` / `winbackAt` / `sentAfterExpiry` |

**二重送信をどう防いでいるか**

- 体験中（`tsudumon.source === 'trial'`）は日次配信の対象外＝B系とC-3が同日に重ならない。
- ライセンスが有効な人には A-5／C-6 を送らない（再登録済みの人に「終了しました」と送らない）。
- 期限終了フォロー（C-6）と未体験フォロー（A-5）が同じ人に当たったら、C-6 を優先して1通に畳む。
- 各送信は Firestore のフラグ（`sentIntro` / `sentAfterExpiry` / `lastSentDate`）で冪等。

**まだ本番に出ていないもの**

- **Hosting（`dist-web/`）**: アカウントページの配信時刻UI・LP文言の修正・ロックカードの
  出し分けは `firebase deploy --only hosting:tsudumon` を実行するまで反映されない。
- `lineWebhook`（一問一答と共有）内のつづもん系文言（つづ先生への改名・期限切れ案内の書き換え）。
  3,000人が使う本番webhookなので、別途まとめてデプロイする。
- Stripe ダッシュボードで `invoice.payment_failed` を webhook の送信対象イベントに**追加**する
  （現在は `checkout.session.completed` / `invoice.paid` / `customer.subscription.deleted` のみの可能性が高い）。
  これを追加するまで C-4（決済失敗の通知）は実際には発火しない。
- **既存の登録者への `tsudumonDaily` 作成**。予定表は決済完了時（`ensureTsudumonDaily`）に作られるため、
  **すでに課金中の人には日次配信が届かない**。必要なら1回だけ埋めるスクリプトを流す。

> ⚠️ **もう1本の日次配信が並行して存在する（2026-07-26・意図的／保留中）**
> `functions/src/sendTsudumonDailyMessage.ts`（つづもん課金者向け「今日のおすすめ」・JST 07:00・
> `.steering/20260725-ai-personal-support/` フェーズ11-2）が `index.ts` から export されている。
> 本ドキュメントの C-3（`tsudumonDailyUnit`）と**対象者が重なる**ため、両方を本番に出すと
> 同じ人に1日2通届く。2026-07-26 時点の状態は「`tsudumonDailyUnit` はデプロイ済み・
> `sendTsudumonDailyMessage` は未デプロイ」で、実配信は1通のみ。
> どちらを本線にするか（あるいは朝＝おすすめ／夜＝今日の1単元と役割を分けるか）は**保留**。
> `sendTsudumonDailyMessage` をデプロイする前に必ずここを読み、重複を解消すること。
- 日次配信は登録者数ぶん毎日1通ずつ増える。**つづもんBotの配信枠**（一問一答とは別勘定）を
  `deliveryStats` の `tsudumonDaily` で毎月確認する。
- LPの「AIが今日の単元を選ぶ」表現は、第1段階の実装（カリキュラム順）に合わせて
  2026-07-26 に修正済み。**AI選定を実装したら、LPの表現も一緒に戻すこと。**

## 4. 実装メモ

- B-0 / C-4 / C-5 / C-6 はいずれも既存のイベント（体験開始API・Stripe webhook）に
  1通ぶら下げるだけで、新しい cron は不要。
- A-5 と C-3 は cron が要る。A-5 は `tsudumonFollowUps` に予定を書いてレンジ走査する
  （`tsudumonTrialReminder` と同じ「レンジ＋limit」パターン。`users` 全件走査はしない）。
- push を足すたびに `deliveryStatsTypes.PushType` に種別を足し、Bot別に集計できるようにする
  （現状 `deliveryStats` はBot混在。つづもん専用キーを増やして識別する）。
