# つづもん 登録フロー設計（LINEファースト・中間案）

作成 2026-07-21。最終更新 2026-07-25。方針決定済み。実装は「決済は後回し・LINE受け皿を先に」(b案) で進め、
2026-07-24〜25 に **ゲート基盤v2・サイレント自動ログイン・3日間無料お試し・Stripe月額サブスク（テストモード）**
まで実装・デプロイ済み（詳細は `.steering/20260724-tsudumon-flow-overhaul/`）。残るのは Stripe 本番キー・
リマインドcronのデプロイ・商品公開判断（末尾「§8 実装状況」参照）。

## 決定事項

- **大方針：LINEを入口にする（LINEファースト）**。ライセンス・つづ先生チャット・AI採点は
  すべて LINE uid の上に乗っているので、Web教材だけ別認証を足さず uid で一貫させる。
- **教材の閲覧ガードは「中間案」**：正規の入口を LINE リッチメニューに集約し、
  初回に uid でライセンス確認 → localStorage に「有効な端末」として記録 → 以降フリー閲覧。
  1コード = 3アカウント（LINE uid 単位）まで。URL 直叩きは noindex ＋ 未確認なら
  体験単元だけ表示、で緩く守る。
  （実装は LIFF ではなく通常Webページ＋自己完結OAuth。2026-07-24 にサイレント自動ログインを追加し、
  LINE内ブラウザではログイン操作なしで即閲覧できるようになった。§4参照）
- **コードは覚えさせない・失わせない**（購入画面を閉じても大丈夫にする）：
  1. 主チャネルはメール（コード・手順・「LINEで受け取る」ボタン・再発行連絡先を1通に）
  2. **コードレス受け取りリンク**を正規導線にする（下記）
  3. 再発行窓口：LINEで「コードがわからない」→ 購入メール/注文番号で照合 → 再送
     （既存 `manage-tsudumon` の info/issue で対応可能）

## 登録フロー（一本道）

1. 購入（LP → Stripe）。決済完了画面＋メールで「①友だち追加 ②受け取り」を案内。
2. **受け取りリンク** `https://www.chatstudy.jp/tsudumon/activate?c=CODE`（メール・完了画面のボタン）
   を開く → LINEログイン（LIFF/LINE Login, `bot_prompt=aggressive` で友だち追加も同時）
   → uid 取得 → **コードを手入力せず自動でライセンス有効化**（既存 handleTsudumonActivation 相当）。
3. リッチメニュー「📖 教材をひらく」→ 通常ページ（`www.chatstudy.jp/tsudumon/map/` 等。LIFF化はしていない）。
   `tzm-lic` に有効な端末記録があれば即閲覧、無ければ `/tsudumon/login/` で LINE内ブラウザなら
   無操作の自動ログイン（2026-07-24 実装。§4参照）→ ライセンス確認して閲覧（ログイン画面を挟まない）。
4. 教材内で解く → 採点に納得いかなければ AI採点ボタン（同 uid、やりとりは LINE トークにも残る）。
5. 複製防止：1コード3アカウント（uid 単位）＋ DL回数制限（既存のまま）。

### 決済（Stripe月額サブスク・1,280円/月・税込）… ✅ 実装・デプロイ済み（2026-07-24〜25・テストモード）

当初案（コード発行→メール送付）から方針転換し、**コードレスの Checkout 直付け**を実装した
（TZM コードは廃止せずギフト・手売り用に併存。詳細設計は
`.steering/20260724-tsudumon-flow-overhaul/design.md` §7）。

- **`tsudumonCreateCheckout`**（`marutto-study/functions/src/tsudumonStripe.ts`）: POST {idToken} →
  Checkout Session（mode=subscription・`client_reference_id`=LINE uid・
  `subscription_data.metadata.uid`=uid）→ `{ok, url}`。体験中（source:'trial'・未失効）の登録は
  残日数を `subscription_data.trial_period_days` に渡し、体験終了後から課金開始（MAX_TRIAL_DAYS=3 で丸め）。
  既に Stripe サブスクが有効なら `already_subscribed` を返し二重登録させない。
- **`tsudumonStripeWebhook`**: 署名検証（raw body・HMAC）。
  - `checkout.session.completed`: `users/{uid}.tsudumon = {plan:'set', source:'stripe', activatedAt, expiresAt}`
    （`expiresAt` = subscription の `current_period_end` + 3日猶予）と `stripeTsudumon={customerId, subscriptionId}` を
    `mergeFields:['tsudumon','stripeTsudumon']` で直接書き込み。`tsudumon_activated` funnel も記録。
  - `invoice.paid`: 継続課金のたびに `expiresAt` を新しい `current_period_end` + 3日猶予に延長（`source==='stripe'` のユーザーのみ。trial/コード有効化には触れない）。
  - `customer.subscription.deleted`: **即失効させない**。ログのみ記録し、`expiresAt` 経過による自然失効に任せる。
- **`tsudumonCreatePortal`**: POST {idToken} → Stripe Billing Portal セッション（解約・カード変更導線）。
- UI: ロックカードに「月額プランに登録（1,280円/月）」ボタン（`tzmStartCheckout`。体験ボタンと同型のログイン往復→Checkout URLへ遷移）。
- Env（`functions/.env`）: `STRIPE_TSUDUMON_SECRET_KEY` / `STRIPE_TSUDUMON_PRICE_ID` / `STRIPE_TSUDUMON_WEBHOOK_SECRET`
  （既存プレミアム用 STRIPE_* とは別系統）。
- ⚠️ **2026-07-25 時点、Stripeはテストモード（本番APIキー未取得）**。テストカード（4242…）で
  Checkout→webhook→Firestore書き込み→解約（自然失効）までのE2Eは検証済み。本番公開には
  本番キーへの差し替え・webhookの本番URL登録・`launch-checklist.md` §A の整合確認が必要。

## §4 サイレント自動ログイン … ✅ 実装・デプロイ済み（2026-07-24）

LINEアプリ内ブラウザ（UA に `Line/` を含む）なら、ロック画面のボタンを押させずに無操作で
LINEログインを往復させる。外部ブラウザ（Safari/Chrome等）は従来どおりボタン式のまま。

- `marutto-study/public/tsudumon/login/index.html` に `?auto=1` を追加。
  `?auto=1` かつ LINE内ブラウザ かつ `sessionStorage['tzm-auto-tried']` 未設定なら、
  ログインボタンを表示せずフラグを立てて即 `access.line.me/authorize` へ遷移。
  それ以外（外部ブラウザ・自動試行済み・OAuthエラー戻り）は現行のボタン表示にフォールバックする。
- 教材側（両生成器 TEMPLATE の `showLock()`）は、ロックカードを表示する直前に
  `tzmMaybeAutoLogin()` を呼ぶ。`window.tzmAuthUser`（module script が公開）が未ログインかつ
  LINE内ブラウザかつ `sessionStorage['tzm-auto-login']` 未設定なら、フラグを立てて
  `../../login/?auto=1&next=<現在地>` へ遷移する（戻ってきて未解錠ならロックカードを表示する
  フォールバック経路）。
- 無限ループ防止は sessionStorage（タブ単位）で「1回だけ自動試行」を担保。
- Callback URL は既存の `/tsudumon/login/` のままで追加登録不要（activate と同じ自己完結OAuthページに集約）。
- 案内メール・受け取りページ成功画面にも「次からはLINEメニュー『📖 教材をひらく』から開くだけ」を追記済み（正規入口の一本化）。

## §5 3日間無料お試し … ✅ 実装・デプロイ済み（2026-07-24）

未購入ユーザーがロックカードの「🎁 3日間無料で試す」ボタンをワンタップすると、
全19単元が72時間（3日間）だけ全開放される。

- **`tsudumonTrialStart`**（`marutto-study/functions/src/tsudumonActivate.ts`）: POST {idToken} →
  `users/{uid}.tsudumon = {plan:'set', source:'trial', years:0, activatedAt, expiresAt: now+72h}` を
  `mergeFields:['tsudumon','tsudumonTrialUsedAt']` で丸ごと置き換え書き込み（体験→本購入時に
  `source:'trial'` 等の旧フィールドが残らない）。
  `users/{uid}.tsudumonTrialUsedAt` を同時に記録し **1 uid 1回**に制限。
  純粋判定 `evaluateTrialEligibility(tsudumonRaw, trialUsedAt, nowMs)`（`tsudumonCore.ts`）が
  `already_licensed`（有効な本ライセンス/体験を保持中は上書きしない）/ `trial_used` / `ok` を返す。
  成功時のみ cron 用 `tsudumonTrials/{uid}` を作成し、`logServerFunnelEvent('trial_started', uid)` を記録。
- **既存のアクセス判定コア（`evaluateTsudumonAccess` / `tsudumonEntitlement` / 教材ゲート / AI採点）は無変更**。
  体験も `users/{uid}.tsudumon` に `plan:'set', expiresAt` を持つだけなので、72時間後は自然に
  `expired` 判定になる。
- ロックカードUI（両生成器 TEMPLATE）: 主ボタン押下→ログイン（LINE内は無操作・外部はボタン、
  `tzm-trial-pending` で往復後も継続）→ `tsudumonTrialStart` 呼び出し→成功で `refreshEntitlement`
  →解錠続行。`trial_used` / `already_licensed` は結果メッセージを表示し、既存の
  「LINEでログイン（購入者の方）」「つづもんを見てみる→」ボタンも維持。
- 期限後の受け皿: 常設無料単元（「律令国家と奈良時代」）＋頭出しへ自然に戻る。
- LP（`pdf-workbook/lp/index.html` hero/FAQ/JSON-LD・cta-banner）・特商法（`lp/tokushoho.html`）・
  LPチャットのナレッジ（`lp/api/chat.js`）を「3日間無料でお試し＋期限後も1単元はずっと無料」に更新済み。
- funnel: `trial_started`（開始時）/ `trial_expired`（期限切れ時）を `logServerFunnelEvent` で記録。

### リマインドcron `tsudumonTrialReminder` … 実装済み・**未デプロイ**

`marutto-study/functions/src/tsudumonTrialReminder.ts` は実装・`index.ts` で export 済みだが、
**本番デプロイはまだ行っていない**（push は公式LINEの配信枠を消費するため、アーム前にユーザー承認が必要）。

- 毎日 JST 19:00 実行予定。`tsudumonTrials` を `expiresAt` レンジ（now±3日）＋`limit(500)` で走査
  （`users` 全体は舐めない）。
- 送信予定は3種（JST暦日基準・1回の実行で緊急度順=期限切れ→前日→翌日のうち1種のみ送信）:
  開始翌日（使い方＋おすすめ単元）／期限前日（あす終了＋購入CTA）／期限切れ後最初の実行
  （`trial_expired` funnel記録＋無料単元案内＋購入CTA）。
- 送信済みは `tsudumonTrials/{uid}.reminded` フラグで管理し重複防止。push は
  `recordPushDelivery('tsudumonTrial')` で `deliveryStats` に計上する実装済み。
- デプロイ手順（承認後）: `firebase deploy --only functions:tsudumonTrialReminder`（名前指定・LINE本番を巻き込まない）。

## §6 ライセンスコード方式（TZM-XXXX-XXXX）との併存

Stripe月額サブスクを実装した後も、コード方式（`activateTsudumonLicense` / `tsudumonActivate`）は
**廃止せずギフト・手売り用に併存**させている。両者は同じ `users/{uid}.tsudumon` を書くため、
`activateTsudumonLicense` の書き込みは `mergeFields:['tsudumon']` に変更済み（2026-07-24）で、
tsudumon フィールドを丸ごと置き換える。これにより体験（`source:'trial'`）中にコードを有効化しても
`source` 等の旧フィールドが残らない。

## §10 保護者導線（子 → 保護者の受け渡し・親子連携）… 実装済み・**未デプロイ**（2026-07-27）

正本設計: `.steering/20260727-parent-handoff/`（requirements / design / tasklist）

### 何を解決したか

`tsudumonCreateCheckout` は idToken から uid を取るため、**保護者が自分の端末で登録すると
保護者自身の uid にサブスクが付き、子の教材は開かない**。つまり「保護者に払ってもらう」
経路が構造的に存在しなかった。中学生本人は決済できないので、ここが唯一の課金経路になる。

### 全体の流れ

```
[子] 体験期限前日/期限切れの push・教材のロックカード・「親に聞かないと」発言
      → 「おうちの人にわたすカード」（reply＝配信枠ゼロ）
      → QR（保護者は自分の端末で読む＝スマホを渡さない）＋台本3種
[親] https://tsudumon.jp/parents/?t=<token>   … 実績サマリ＋結論3行＋見える/見えない表
      ├─① 登録する → Stripe Checkout（課金先は【子】のuid・paidBy=parent）
      └─② 公式LINEでつながる → 保護者ダッシュボード（きょうだい可）
```

**決済に LINE 連携を必須にしない**。②は決済完了画面から任意で誘う（連携を先に要求すると、
いちばん熱がある瞬間に友だち追加とOAuthを挟むことになり落ちる）。

### 追加した Cloud Functions

| 関数 | 役割 |
|---|---|
| `tsudumonInviteCreate` | カード発行（子）。`tsudumonInvites/{inviteId}` を作る。1人1枚（再発行で旧doc削除） |
| `tsudumonInviteView` | カード閲覧（保護者・**LINEログイン不要**）。初回だけ子へ1通push |

### トークン

`t = <inviteId>.<HMAC-SHA256(inviteId, TSUDUMON_INVITE_SECRET) 先頭32hex>`
inviteId はランダム22文字。**URL に uid を載せない**。有効期限14日。失効は doc 削除で即効。

### プライバシー（この機能の転換率そのもの）

保護者に見せるのは学習の記録だけ。**トーク内容・記述解答・まちがえた問題（件数も）は出さない。**
件数すら出さないのは、「間違えると親に見られる」と学習した子がわざと簡単な問題だけを解く
ようになり、学習データ自体が壊れるため（2026-07-27 ユーザー判断）。

担保は文言ではなく**構造**:
- `tsudumonParentDashboard.ts` は会話・解答のモジュールを **import しない**
- `tsudumonParentCore.ts` は `unitsNeedingReview`/`topWrongQids`/`wrongLeft` を呼ばない
- 保護者モードのAIプロンプトは子の学習文脈を差し込まない
- 上記3つを `__tests__/tsudumonParentPrivacy.test.ts` で固定

連携は**子が発行したカード経由のみ**。保護者から子を検索・指定する口は作らない。

### きょうだい

1人1契約。**2人目以降は月額980円**（`STRIPE_TSUDUMON_PRICE_ID_SIBLING`）。
割引は**公式LINE連携済みの保護者にのみ**適用する（決済時点で「同じ世帯の2人目」と
判定できる材料が連携情報しかないため）。結果として割引が連携の動機になる。
Price 未設定なら通常価格へフォールバックし、決済は止めない。
