## 2. 改善案と順番

### フェーズA（着手）テスト日・範囲を登録できるようにする

**要件（ユーザー指示 2026-07-26）**: 生徒は**範囲を正確に知らないことが多い**。
だから入力フォームではなく、**チャットで相談しながら目星をつけて登録**できる形にする。

- AIが「学校でいまどのあたり？」「前のテストはどこまでだった？」と単元名で聞き、候補を提示する
- 生徒が「たぶんこのへん」と言えれば、**確度 `estimated` として登録**してよい（完璧を求めない）
- 分かっている場合は `confirmed`。あとから会話で修正できる
- 登録すると日次配信がその範囲に切り替わる

### フェーズB（着手）日次配信の単元選びを学習状況ベースにする

優先順位: ①テスト範囲の中で間違いが残る章 → ②テスト範囲の未着手 → ③範囲外で間違いが残る章 → ④カリキュラム順

### フェーズC 学校の進度を月1回だけ聞く

19択のボタンで十分。教科書会社別の対応表を作るより、本人に聞くほうが速くて正確。

### フェーズD ニガテの自動再出題（間隔反復）

3日後・1週間後・2週間後に「あの問題、もう一度いける？」をトーク内で。Webを開かず完結するのが要点。

### フェーズE LINEのトークから直接1問

「1問ちょうだい」で出す。reply送信なので配信枠を消費しない。

### フェーズF Web内チャットを長期記憶（`aiThreads`）へつなぐ

いまは直近8ターンで消える。繋ぐと「先週ここでつまずいてたね」が言える。
※ 無料ユーザーも使う経路なので、課金者・体験中のみ積む案が有力（保留中）。

### フェーズG マップのサーバ連動 ／ H 連続学習日数・レベル ／ I 保護者への週次レポート

G は端末間で進捗が揃い、LINEからも「7/19マス」と言えるようになる。
I は解約抑止に直結する（LPの「がんばりが見える」の約束）。

**I の前提は 2026-07-27 に実装済み**（`.steering/20260727-parent-handoff/`・未デプロイ）:
保護者が公式LINEで子と連携し、`tsudumon.jp/parents/dashboard/` で学習の記録を見られる。
日別ログ `tsudumonProgress.days` も入ったので、**週次レポートの配信だけ**が残っている。
⚠️ 保護者に出すのは学習の記録のみ。トーク内容・記述解答・まちがえた問題（件数も）は出さない。

### フェーズJ（済・2026-07-27）保護者への受け渡し導線

中学生本人は決済できないので、ここが唯一の課金経路。保護者ペイリンク（保護者が自分の端末で
子のアカウントに課金できる）・子が渡すカード（QR＋台本）・親子連携（きょうだい可）・
保護者ダッシュボード。正本は `docs/つづもん-登録フロー設計.md` §10。

## 4. 次に実装する（設計確定・2026-07-26）

### 4-1. 学習モード（定期テスト／入試／両立）

`users/{uid}.tsudumonMode` = `exam` / `entrance` / `both`。**未設定は学年から自動判定**
（中1・中2 = `exam` ／ 中3 = `both`）。あとから会話・アカウントページで変更可。

- `exam`: テスト範囲のみ（現行 `pickDailyUnit` のまま）
- `entrance`: 弱い章（正答率低い・未着手）＋最後にやってから日が経った章を優先し、全19単元を周回
- `both`: テスト日の**14日前で自動的に `exam` へ切替**、終了後 `entrance` に戻る。切替時は理由を伝える
- 追加: `setStudyMode` ツール／入試モードの可視化（周回数・正答率の推移）

### 4-2. リッチメニュー（6ボタン・2×3）

| 位置 | ラベル | 動作 |
|---|---|---|
| 左上 | 📖 教材をひらく | **postback**（下記 4-3。トップと「おすすめ」の両方を出す） |
| 中上 | 📅 テストの予定を伝える | message「テストの予定を登録したい」 |
| 右上 | 🔁 まちがえを復習 | message「復習する」 |
| 左下 | 📊 学習の記録をみる | message「いまの学習状況を教えて」 |
| 中下 | ⏰ 届く曜日・時間 | uri `https://tsudumon.jp/account/` |
| 右下 | ⚙️ お支払い・解約 | uri `https://tsudumon.jp/account/` |

※「つづ先生に質問」は置かない（普通に打てば答えるため。ボタンにする価値があるのは
「その言い方をしないと発動しないもの」だけ）。

**左下の枠は運用で入れ替える（ユーザー決定 2026-07-26）**

| 時期 | 左下のボタン | ねらい |
|---|---|---|
| **公開初期** | 🎁 3日間無料でためす（uri `account/?do=trial`） | **獲得**。リッチメニューは友だち全員に出るので、未登録者にとって最強の入口 |
| **登録者が増えたら** | 📊 学習の記録をみる（message「いまの学習状況を教えて」） | **継続**。積み上げが見えると次の1単元につながる |

入れ替えは `setup-tsudumon-richmenu.ts` を再実行するだけ（画像も差し替えが必要なので、
CODEXブリーフは**左下だけ違う2種**を用意しておく）。

### 4-3. 「教材をひらく」は2択を返す（✅ 実装・デプロイ済み 2026-07-26）

実装は `functions/src/tsudumonOpenMaterial.ts`（純粋な文面ビルダー＋ハンドラ）、
配線は `functions/src/tsudumon/webhook.ts` の `case 'tzm_open'`。以下は設計の記録。


リッチメニューの1枠では静的URLしか置けないが、「おすすめ」はユーザーごとに変わる。
そこで **postback で受けて reply で2択を返す**（reply なので配信枠ゼロ）。

```
postback type=tzm_open
  → users/{uid} と tsudumonDaily/{uid} を読む（各1 read）
  → pickDailyUnit で「いまやるとよい章」を決める
  → reply:
      ▶ つづきから（おすすめ）… /wb/{no}/ ＋ /ref/{no}/
        枕は pickReasonLead（「テストまであと◯日だから範囲の…」等）
      🗺 教材トップ（歴史クエスト）… /map/
```

- 判定材料（テスト範囲・間違いの残り・カーソル）は既存のものをそのまま使う
- 学習記録が無い人には「まずは第1章から」と案内し、トップも併記する
