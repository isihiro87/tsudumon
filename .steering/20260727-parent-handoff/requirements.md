# 要求内容 — つづもん「子 → 保護者」受け渡し導線

作成 2026-07-27。関連: `docs/つづもん-登録フロー設計.md`（登録・ゲート）/ `docs/つづもん-機能ロードマップ.md`
（フェーズI「保護者への週次レポート」）/ `lp/parents.html`（既存の保護者向けページ）。

## 概要

3日間の無料体験を使った中学生が、**自分の言葉で保護者にお願いでき、保護者が自分のスマホだけで
申し込みを完了できる**ようにする。中学生本人は決済できないため、ここが唯一の課金経路であり、
サービスが広がるかどうかの分岐点になる。

あわせて、**保護者が公式LINEに登録すると子のアカウントと連携**し（きょうだい複数可）、
**学習の記録だけを見られる保護者ダッシュボード**を持つ。**トークの内容は保護者に一切公開しない。**

## 背景

### 1. いま「親に払ってもらう」経路が技術的に存在しない（最大の問題）

`tsudumonCreateCheckout`（`marutto-study/functions/src/tsudumonStripe.ts`）は
**POST {idToken} → LINE uid** で Checkout Session を作り、`client_reference_id` に子の uid を載せる。
つまり課金は「LINEにログインしている本人」にしか紐づかない。

保護者が自分のスマホで `tsudumon.jp` を開いて登録すると、**保護者自身の LINE uid にサブスクが付き、
子の教材は一生開かない**。現実に取れる手段は「子のスマホを親に渡して操作してもらう」だけで、
中学生にとってこれは心理的にかなり重い（トーク履歴を見られる）。

**「案内しやすくする」以前に、案内した先の受け皿が塞がっている。**

### 2. 子が親に切り出すための材料が何もない

体験中の学習実績（学習時間・解いた問題数・正答率・進んだ単元）は `users/{uid}.tsudumonProgress` に
既に溜まっているが、**外に出す手段がない**。「勉強したい」と自分から言っている証拠は、保護者に対して
いちばん強い説得材料なのに使われていない。

さらに中学生が最も詰まるのは「なんて言えばいいか分からない」ことで、金額の話を自分から切り出すのは
大人が思うより難しい。台本が要る。

### 3. 保護者側のページはあるが、たどり着けない・長い

`lp/parents.html` は内容（料金・解約・AIの安全性・通知の量）は充分だが、

- **子から親へ渡す導線がない**（LPの下部リンクのみ。子はこのページの存在を知らない）
- **文脈がない**（「お子さんが送ってきました」の一言がなく、いきなり事業者の説明から始まる）
- **実績が入らない**（一般論なので「うちの子がどうだったか」が分からない）
- 冒頭に結論（いくら・いつでも解約・何が届くか）がなく、判断に時間がかかる

### 4. 出すタイミングの受け皿（体験リマインド）が未デプロイ

`tsudumonTrialReminder` は実装済み・**未デプロイ**（`docs/つづもん-登録フロー設計.md` §5）。
3日間の体験に現状リマインドが1通も届かない。「親にお願いする」を出す最良の瞬間（体験2日目の夜・
期限前日）がそもそも存在しないので、この導線と一緒にアームする必要がある。

## 実装対象の機能

### 1. 保護者ペイリンク（保護者が自分の端末で、子のアカウントに課金できる）

- 子の uid を**署名付き短命トークン**に封じた URL を発行する（LINEログインを保護者に要求しない）
- 保護者がその URL から決済すると、**子の uid** に月額プランが付く
- 決済後は既存の webhook 経路（`checkout.session.completed`）に合流し、子への御礼push・
  日次配信の開始・`users/{uid}.tsudumon` の書き込みは現行のまま動く
- 誰が払ったか（`paidBy: 'parent' | 'self'`）を記録する

### 2. おうちの人にわたすカード（子側）

- LINEトーク内で「おうちの人に見せる」を選ぶと、**保護者ページの URL 付きメッセージ**が返る
  （reply＝配信枠ゼロ）
- 同時に **子の画面に出す QR コード**を用意する。保護者は自分のスマホで読み取るだけで開けるので、
  「スマホを渡す／トーク履歴を見られる」を回避できる
- **そのまま言える一言（台本）を3パターン**添える。金額・お試しの結果・解約できることを
  中学生の語彙で先に言えるようにする

### 3. 保護者ページのパーソナライズ（`/parents/?t=<token>`）

- 冒頭に「お子さんから届いています」の文脈と、**体験中の実績サマリ**（学習した日数・時間・
  解いた問題数・正答率・進んだ単元）を出す
- その直下に**結論3行**（月1,280円・いつでも解約・LINEに1日最大2通）と申し込みボタン
- 既存 `lp/parents.html` の詳細（料金／通知／AIの安全性／がんばりの見方）はそのまま下部に残す
- トークン無しで開いた場合は**従来どおりの一般ページ**として成立する（実績部分を出さないだけ）

### 4. 出すタイミング（4か所）

| # | 契機 | 出し方 |
|---|---|---|
| A | 体験2日目の夜 | `tsudumonTrialReminder` の day2 に「続けたかったら、おうちの人に見せるカードを出せるよ」 |
| B | 体験期限の前日 | 同 day3 の主CTAを「おうちの人にお願いする」に |
| C | 体験終了後に教材を開いたとき | 教材のロックカードに「おうちの人にお願いする」ボタン（月額登録ボタンと並置） |
| D | 子が「親に聞かないと」「お金が…」と言ったとき | つづ先生（AI）がカードを出す |

### 5. 保護者が見たあとのフォロー（1回だけ）

- 保護者ページが開かれたら、子に1通だけ「見てくれたみたい」と伝える
- 決済に至らなかった場合の追撃は**しない**（子と保護者の関係に踏み込まない）

### 6. 親子アカウント連携（保護者が公式LINEに登録したとき）

- 保護者がつづもん公式LINEを友だち追加し、**子が発行したカード経由**でのみ連携が成立する
  （保護者から一方的に子を検索・指定して繋ぐ手段は作らない）
- 保護者1人に対し**子は複数**（きょうだい。上限4人）。子1人に対し保護者は上限2人
- 連携すると保護者側は「保護者モード」になり、日次配信（今日の1単元）の対象にならず、
  リッチメニュー・AIの応対も保護者向けに切り替わる
- 連携の成立・解除は**子にも必ず通知**する。子はいつでも自分から連携を解除できる

### 7. 保護者ダッシュボード（学習の記録のみ）

- `tsudumon.jp/parents/dashboard/` を保護者のLINEログインで開くと、連携中の子が**並んで**表示される
- 子ごとに見えるもの: 呼び名・学年・契約状態（体験中／◯月◯日まで／期限切れ）・直近7日の学習日数・
  学習時間（今週／累計）・進んだ単元数（◯/19）・解いた問題数・正答率・最後に学習した日
- 子ごとに「お支払い・解約」ボタン（Stripe Billing Portal）

#### 保護者に公開しないもの（設計上の絶対条件）

- **トークの内容全般**（つづ先生とのやりとり、質問文、悩み相談、AIへの入力）
- 記述問題の**解答本文**、AI採点の講評文
- **間違えた問題そのもの**（「まちがいが残っている数」だけを出し、問題文・誤答内容は出さない）
- 本名・学校名・住所などの個人情報（そもそもシステムが保存しない）

> これは「APIのレスポンスから削る」のではなく、**保護者向けAPIが会話・解答本文のコレクションに
> 一切アクセスしない**構造で担保する。

### 8. 計測

- `parent_link_created` / `parent_page_viewed` / `parent_checkout_started` を funnel に追加
- `tsudumon_activated` に `paidBy` を付け、**保護者経由の成約率**を単独で見られるようにする

## 受け入れ条件

### 保護者ペイリンク
- [ ] 保護者の端末（LINE未ログイン・別ブラウザ）から決済して、**子の uid** に `tsudumon.plan='set'` が付く
- [ ] トークンは有効期限つき（14日）で、期限切れ・改ざん時は決済に進めず案内文を出す
- [ ] トークンに LINE uid が平文で含まれない（URLからuidを復元できない）
- [ ] 体験中に保護者が登録した場合、既存と同じく残り体験日数ぶん課金を遅らせる（`trial_period_days`）
- [ ] すでに有効なサブスクがある場合は二重登録させない（`already_subscribed` と同等の表示）
- [ ] 決済後、子のLINEに既存の御礼push＋オンボーディングが従来どおり届く

### おうちの人にわたすカード
- [ ] LINEトークから1タップで、URL・QR・台本にたどり着ける
- [ ] QRは保護者の端末で読み取れ、子のスマホを渡さずに完結する
- [ ] 台本は中学生が読み上げられる長さ（各2〜3文）で、金額と解約の自由を含む

### 保護者ページ
- [ ] トークン付きで開くと、実績サマリが表示される
- [ ] トークン無しで開いても、従来の `parents.html` 相当として破綻しない
- [ ] 実績サマリに本名・学校名・住所などの個人情報が一切出ない
- [ ] スマホ縦画面で、**スクロールせずに**「いくら・解約できる・申し込みボタン」が見える

### タイミング・フォロー
- [ ] A〜D の4か所からカードに到達できる
- [ ] 保護者ページ閲覧の通知は子へ**1通だけ**（同一トークンで何度開かれても再送しない）

### 親子連携
- [ ] 子が発行したカードからのみ連携が成立し、それ以外の経路では成立しない
- [ ] 同一保護者が、子A・子Bのカードを順に開くと**2人とも**連携される（きょうだい対応）
- [ ] 連携した保護者に「今日の1単元」の日次配信が届かない
- [ ] 保護者がつづ先生に話しかけると、保護者向けの応対（敬語・料金/解約/使い方）になる
- [ ] 連携成立・解除の両方が、子のLINEに通知される
- [ ] 子が「保護者の連携を解除」と言うと解除でき、保護者のダッシュボードから消える
- [ ] 既に一問一答Bot（`@824cebif`・3,000人・無料）の友だちである保護者が連携しても、
      一問一答側の挙動が一切変わらない

### きょうだい割引
- [ ] 連携済みの保護者が2人目の子を登録すると、2人目のサブスクが 980円/月 で作られる
- [ ] 未連携の保護者が登録した場合は 1,280円/月（1人目扱い）で作られる
- [ ] 2人目のカード閲覧画面と決済完了画面に「連携すると2人目から割引」が明示される
- [ ] 1人目を解約しても、残った2人目の価格は変わらない（優しい側に倒す）

### 保護者ダッシュボード
- [ ] 連携中の子が複数いれば全員分が並ぶ
- [ ] **「まちがいが残っている件数」がレスポンスにも画面にも含まれない**
- [ ] **トーク内容・記述解答本文・間違えた問題文がレスポンスに一切含まれない**
      （APIが該当コレクションを読まないことをコードで確認できる）
- [ ] 連携していない子のデータは、uid を知っていても取得できない
- [ ] Firestore の read が「保護者1件＋子の人数」で収まる（コレクション走査をしない）
- [ ] 子ごとに Stripe Billing Portal を開ける

## 成功指標

- **体験終了者のうち、保護者ページに到達した割合**（一次指標。ここが全ての上限になる）
- 保護者ページ到達 → 決済完了率
- 全成約に占める `paidBy='parent'` の割合
- 成約した保護者のうち、公式LINEに連携した割合（解約抑止の先行指標）
- きょうだい連携が発生した世帯数（1世帯あたり単価に直結）
- （定性）中学生が「親に言いづらい」「監視されそう」で止まらないこと

## スコープ外

以下はこのフェーズでは実装しない:

- 保護者への**定期**レポート配信（週次/月次push。ロードマップ フェーズI。連携が動いてから別建て）
- Stripe customer のきょうだい統合（当面は子ごとに独立した customer・subscription）
- 未連携で2人分払ってしまった保護者への**自動**差額調整（問い合わせでの個別対応とする）
- 保護者から子への声かけ機能（応援スタンプ等）
- 保護者による学習設定の変更（配信時刻・テスト範囲は本人が持つ）
- 決済手段の追加（コンビニ払い・キャリア決済など）
- 紙のチラシ・印刷物の設計

## 前提・依存

- **`tsudumonTrialReminder` の本番デプロイ**（未実施・ユーザー承認待ち）。A・B はこれに乗る
- Stripe 本番キー（`docs/つづもん-登録フロー設計.md` §8）
- 独自ドメイン `tsudumon.jp` への移行（`dist-web` 出力・未デプロイ）
- つづもんBot の**保護者用リッチメニュー**（画像が要る。子用と別デザイン）

## 決定事項（2026-07-27・ユーザー判断済み）

1. **きょうだい料金は「1人1契約＋2人目以降を割引」**。1人目 1,280円／2人目以降 980円（既定値・
   変更可）。**割引は公式LINE連携済みの保護者にのみ適用**する（決済時点で「同じ世帯の2人目」と
   判定できるのが連携情報だけのため）。結果として割引が連携の動機になる。
   現行 `lp/parents.html` の「1契約で家庭内利用可・記録は1つにまとまる」は書き換える。
2. **「まちがいが残っている件数」は保護者に出さない**。件数だけでも詰める材料になり、
   「間違えると親に見られる」と学習した子はわざと簡単な問題だけを解くようになり、
   学習データ自体が壊れる。保護者に出す精度指標は正答率のみとする。
3. **子の呼び名は本人に一度だけ聞く**（`tsudumonParentName`）。LINE表示名は本名のことが多く、
   「本名・学校名は保存しない」方針と衝突するため流用しない。既定候補として学年を出し、
   無回答でも進める。
